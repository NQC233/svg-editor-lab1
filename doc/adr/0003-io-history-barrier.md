# 文档命令建立不可跨越的历史屏障

Status: accepted (2026-10-22)

课程规定 `init`、`read`、`save` 和修改尺寸的 `canvas` 执行后禁止 undo/redo，直到下一次编辑命令。我们进一步决定：成功的文档命令立即清空 undo 和 redo 栈并锁定历史；下一次**改变状态**的编辑命令解锁并从空历史开始。失败的文档命令不清空、不锁定；无操作编辑命令也不解锁。

`read` 和 `init` 会替换整个文档，旧命令持有的图形引用已经失效，保留旧历史会产生悬空对象。`save` 和 `canvas` 虽然不替换文档，但课程把它们定义为同类屏障；统一清空后，撤销永远不会跨过一次 IO 或画布尺寸变更，用户不需要猜测“还能撤销到哪一步”。

代价是 `save` 之后无法撤销保存前的编辑，即使保存本身没有改变内容；这是对课程规则的直接实现。若未来需要跨 IO 的持久历史，应引入带文档版本标识的历史条目，而不是简单保留旧命令对象。
