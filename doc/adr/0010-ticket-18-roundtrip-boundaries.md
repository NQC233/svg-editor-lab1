# Ticket 18 的补 id、元数据与未建模属性边界

Status: accepted (2026-10-25)

用户确认 Ticket 16、17 已交付并授权实现 Ticket 18。为解除该票的 `needs-info` 门禁，本次收口读取警告、元数据忽略和未建模属性往返规则：

- 先按文档顺序遍历全部图形元素并收集显式 id；显式 id 重复或含空白字符时整份读取失败。再按同一顺序为缺失或空字符串 id 的图形分配 `<tag><n>`，从 1 开始选择第一个未被显式或已分配 id 使用的值，大小写敏感。
- 自动补 id 的警告先保存在读取结果中，只有文件读取、XML 解析、结构校验、图形构造和 id 分配全部成功后才由 `read` 输出；失败不泄露任何警告。
- `title`、`desc`、`metadata` 及其整棵子树在 `svg`、`g`、叶子和 `text` 中忽略，不计入元素数，也不校验其内部元素。元数据之外的未知元素仍按支持子集拒绝。
- `text` 的直接文本和 CDATA 都计入正文；其他元素的 CDATA 仍按 ADR-0009 忽略。元数据子元素不进入正文。
- 六种图形上的未知属性作为未建模属性按读取顺序封装；写出时放在 `id`、几何属性、`fill`、`stroke`、`stroke-width` 之后，并保持它们彼此的相对顺序。根元素上的未知属性仍按现有规则忽略。
- 未建模属性不参与 `move`、`scale` 或 `set`，不出现在 `tree`/`show`，也不改变已有图形多态或按名字创建入口。`transform`、`style`、以 `on` 开头的事件属性和未知视觉元素继续拒绝。

这样支持子集内的读写往返保留可观察的领域树和未建模属性，同时不把未知结构误当成可编辑模型。代价是元数据不参与往返，未知根属性也不保留；两者都是当前规格明确接受的范围。
