# group 子节点保持分组前的文档相对顺序

Status: accepted (2026-10-25)

课程要求 `group` 从各自原父容器摘出目标时“保持相对顺序”，但没有说明目标来自多个父级时的比较范围。2026-10-25 用户以原同级顺序 `a,b`、命令 `group g b a` 为例确认最终子节点顺序必须是 `a,b`，不能按命令行参数顺序改成 `b,a`。因此本文取代 [ADR-0004](./0004-group-anchor-rule.md) 中“子节点按命令行顺序排列”的部分。

`group <newGid> <id1> <id2>…` 的规则如下：

- 新容器的父级和插入位置仍取**第一个命令行目标**分组前的父级和位置；该插入位置换算为摘出全部目标后，原父级中第一个目标之前剩余的非目标兄弟数量。
- 新容器的子节点按分组前整棵文档树的先序遍历顺序排列。同一父级的目标保持原兄弟顺序；跨父级的目标以它们在文档中的先后关系为准。
- 拒绝重复目标、缺失目标以及目标集合中同时包含容器及其子孙；后者的错误目标按命令行顺序选择第一个包含其他目标的容器。
- 撤销按各目标原父级和原索引恢复，先移除新容器，再对每个父级按原索引升序插回。

这个规则直接满足课程“保持相对顺序”，且不改变 ADR-0004 已确认的首目标锚点语义。代价是跨父级分组时，新容器的子节点顺序不能由参数顺序控制；这符合本阶段“收编已有图形”而不是“按新顺序排列”的目标。
