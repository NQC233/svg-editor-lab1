# group 以第一个 id 为父级和位置锚点，子节点按命令行顺序排列

Status: accepted (2026-10-22)

`group <newGid> <id1> <id2>…` 的语法没有 `in` 子句，但目标可以来自不同父级。我们决定：新容器的父级和插入位置取**第一个目标**分组前的父级和索引；其余目标从各自原父级摘出；新容器内的顺序等于命令行列出的顺序。目标集合中同时包含容器和它的子孙时，在修改前拒绝并报 `cannot group a container into its own descendant: <id>`。

这样规则只有一句“第一个 id 是锚点”，实现和解释都直接；它也和课程的错误例子一致：`group bad c1 markers` 中 `c1` 的父级是 `markers`，新组建在 `markers` 内，再把 `markers` 放进去就形成环，必须在修改前拒绝。代价是跨父级分组时参数顺序会影响新组所在层级；用户需要把希望新组所在父级里的图形写在第一位。曾考虑“总放在画布根”（会破坏局部层级）、“最近共同父容器”（插入位置还需另一套规则）和“要求同一父级”（与课程“从各自原父容器摘出”冲突），均未采用。
